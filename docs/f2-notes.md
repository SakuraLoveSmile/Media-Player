## 2. 实测步骤（macOS 26/27，release）

1. 启动（已有会话）→ 直接进入库页，不再是登录页。
2. `GET /Users/{id}/Views` 返回 13 个库，chips 横向可滚动。
3. 首个视图 `GET Items`（Limit=60）返回 58 条；海报 URL 带 `maxWidth=320&quality=90&api_key=...`，全部 200。
4. 右上角刷新按钮可重新拉取；下拉/滚到底触发下一页（当前库不足一页，无第二页请求）。

## 3. 交互与状态

| 场景 | 行为 |
|---|---|
| 首屏加载 | 居中进度圈；视图 chips 在数据到达后出现 |
| 切换视图 | 清空当前网格 → 重新拉第一页；`loading` 期间忽略重复切换 |
| 滚动到底 | 距底部 400px 触发 `loadMore`；`StartIndex` 取已加载条数；到 `TotalRecordCount` 停止 |
| 加载更多失败 | 保留已加载条目，顶部错误提示，可重试；不阻断浏览 |
| 空库 | 「这个库还没有内容」 |
| 无视图 | 「服务器没有可浏览的媒体库」 |
| 网络失败 | 「无法连接服务器，请检查网络」+ 重试；失败优先于"无视图"提示 |
| 401 | 会话已清空 → 自动回登录页，不显示错误条 |
| 已看 | 海报右上角「已看」标记（来自 `UserData.Played`） |

## 4. 实现要点

1. `LibraryController extends ChangeNotifier`：纯状态机，不依赖 BuildContext，可单独单测；页面只负责渲染与滚动触发。
2. 首屏失败与"服务器没有视图"分开判断：先判断 error，再判断空视图，避免把网络故障显示成"没有媒体库"。
3. 加载更多不并发：`loadingMore` 互斥；切库后旧请求返回会被丢弃（比对 `selectedView.id`）。
4. 海报用 `Image.network`（URL 内已带 `api_key`），无新增缓存依赖；加载失败显示占位图标。
5. 卡片点击进入 `/player/:itemId` 占位页；真正的详情/季集与播放属于 F3。
